# Каталог правил и двуязычный паритет

[English](../rule-catalog.md) | [Русский](rule-catalog.md)

В состав Qriterra входит структурированная база знаний из **80 запахов кода**. Этот документ описывает структуру каталога, механизмы проверки двуязычного паритета, оптимизацию промптов и способы фильтрации или расширения базы правил.

---

## 1. Файлы и структура каталога

Файлы базы правил упакованы в каталог реализации, сохраняемой для совместимости: `agent_code_checker/profiles/data/`:

| Файл | Назначение |
|---|---|
| `code_smells.min.json` | Каноническая русскоязычная база знаний (80 запахов кода на уровне методов, классов и архитектуры). |
| `code_smells.en.json` | Полный зеркальный перевод на английский язык всех текстовых описаний. |
| `code_smells.en.sha256` | Контрольная сумма SHA-256 файла `code_smells.min.json`. Гарантирует актуальность английского перевода. |
| `code_smells.schema.json` | JSON Schema для валидации полей и структуры базы правил. |

---

## 2. Двуязычный паритет и строгая валидация

Точное смысловое соответствие между русской и английской версиями базы проверяется при каждой загрузке функцией `_validate_translation_shape()` в `agent_code_checker/catalog.py`:

1. **Структурная идентичность**:
   - Английский JSON полностью повторяет иерархию, ключи, порядок правил и длину массивов оригинала.
   - Все идентификаторы `id`, категории, уровни критичности (`severity`) и области (`scope`) строго совпадают.
2. **Неизменность примеров программного кода**:
   - Код внутри `bad_example.code` и `good_example.code` копируется дословно. Имена переменных, сигнатуры функций и синтаксис не переводятся, что исключает искажение их поведения.
3. **Сохранение численных метрик**:
   - Численные пороги в `detection_metrics` (например, `> 85% совпадения токенов`, `LOC > 30`, `цикломатическая сложность > 10`) перенесены без изменений и округлений.
4. **Автоматический пайплайн перевода**:
   - Зеркало сгенерировано скриптом `scripts/translate_catalog.py` через Google Antigravity. Скрипт сохраняет инкрементальные чекпоинты в `.runtime/catalog-translation/` и валидирует каждое поле.
   - Если исходный файл `code_smells.min.json` изменяется, а зеркало не обновлено, загрузчик отклоняет устаревший перевод с ошибкой `CatalogError`.

## 3. Поля правил: глубина каталога и оптимизация промптов

Каждая запись каталога содержит подробные обучающие и диагностические метаданные:
- `id`: уникальный строковый ключ (например, `long_method`, `duplicate_code`, `god_object`).
- `name` / `name_en`: названия на русском и английском языках.
- `severity`: критичность (`"low"`, `"medium"`, `"high"`, `"critical"`).
- `level` (`scope`): уровень гранулярности (`"method"`, `"class"`, `"file"`, `"subsystem"`, `"architecture"`).
- `summary` и `definition`: краткое и полное определение архитектурного дефекта.
- `symptoms`: внешние признаки проявления проблемы в кодовой базе.
- `detection_metrics`: численные ориентиры и эвристические показатели.
- `root_causes` и `impact`: первопричины возникновения и влияние на технический долг.
- `refactoring_techniques`: рекомендуемые приёмы устранения нарушения.
- `bad_example` и `good_example`: примеры некорректного и исправленного кода с пояснениями.

### Оптимизация контекста промпта

Для минимизации расхода токенов и предотвращения генерации нежелательного рефакторинга метод `RuleDefinition.prompt_dict()` исключает вспомогательные поля при отправке запроса модели:

```text
Отправляется агенту в промпте:
├── id
├── title (на русском или английском в зависимости от prompt_language)
├── severity
├── scope
├── summary
├── definition
├── symptoms
└── detection_hints (detection_metrics)

Исключено из промптов:
├── root_causes
├── impact
├── refactoring_techniques
├── bad_example
└── good_example
```

Исключение примеров кода и описаний рефакторинга сохраняет фокус модели исключительно на **обнаружении** дефектов и экономит тысячи токенов на каждом пакете.

## 4. Выбор языка правил (`--prompt-language`)

Параметр CLI `--prompt-language` и одноимённый аргумент в Python управляют языком формулировок, передаваемых модели:

- **`auto` (по умолчанию)**:
  - При использовании встроенной базы автоматически выбирается **`en`** (английское зеркало).
  - При подключении внешней базы через `--catalog` выбирается **`ru`** (русский).
- **`en`**:
  - Использует проверенный английский перевод.
  - Доступен только для встроенной базы. При попытке передать `en` вместе с `--catalog` выбрасывается `CatalogError`.
- **`ru`**:
  - Передаёт модели канонические русские формулировки напрямую из `code_smells.min.json`.

## 5. Выбор отдельных правил и внешние каталоги

### Выборочная проверка правил

По умолчанию чекер оценивает все 80 правил. С помощью флага `--rules` можно ограничить проверку списком идентификаторов:

```powershell
qriterra evaluate file src/orders.py `
  --rules long_method,complex_conditional,primitive_obsession
```

В коде на Python:

```python
profile = load_code_smells_profile(
    rule_ids=["long_method", "duplicate_code"],
    prompt_language="en",
)
```

Если передан несуществующий идентификатор правила, `load_code_smells_profile` немедленно завершит работу с ошибкой `CatalogError` до отправки запросов к модели.

### Использование собственного каталога

Вы можете подключить свой JSON-файл базы правил через параметр `--catalog`:

```powershell
qriterra evaluate project path/to/repo `
  --catalog path/to/custom_rules.json `
  --prompt-language ru
```

Пользовательский каталог обязан соответствовать структуре `code_smells.schema.json`, а значение `meta.total_smells` должно в точности совпадать с количеством записей в массиве `smells`.
