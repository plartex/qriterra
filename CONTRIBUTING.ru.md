# Руководство для разработчиков (Contributing)

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Спасибо за интерес к развитию проекта **Qriterra**. Библиотека разрабатывается в соответствии с принципами тест-ориентированной разработки (TDD), высокого покрытия тестами без расхода квот и строгого двуязычного паритета документации.

---

## 1. Принципы разработки

1. **Разработка через тестирование (TDD)**:
   - Перед исправлением ошибки или добавлением функциональности создавайте падающий unit- или контрактный тест.
   - Поддерживайте высокое тестовое покрытие моделей, валидаторов, генераторов промптов и исполнителей.
2. **Оффлайн-тесты с нулевым расходом квот**:
   - Основной тестовый набор должен выполняться полностью автономно без подключения к реальным LLM-провайдерам, без траты платных токенов и без сетевых ключей.
   - Для симуляции ответов моделей, генерации ошибок и сессий используется `FakeAgentProvider`.
3. **Изолированная архитектура**:
   - Qriterra не должен зависеть от внутренней реализации харнессов Agent Shuttle. Agent Shuttle является исключительно клиентом внешнего A2A-транспорта.
   - Запрещено коммитить изменения в репозиторий Agent Shuttle из рабочей области Qriterra.
4. **Двуязычный паритет документации**:
   - Английская версия является канонической; русская — её семантически точным отражением.
   - Любое изменение документации в `docs/*.md` обязано сопровождаться эквивалентным обновлением в `docs/ru/*.md`.
   - Любая правка в `code_smells.min.json` должна быть отражена в `code_smells.en.json` с актуализацией хеша в `code_smells.en.sha256`.

## 2. Настройка рабочего окружения

Клонируйте репозиторий и настройте виртуальное окружение с Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e "path/to/agent-shuttle" -e .
```

---

## 3. Запуск тестов

### Быстрый автономный тестовый набор

Запуск полного набора unit-тестов, проверки каталога и разрешения провайдеров:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Автономный набор тестов должен проходить без обращения к реальному харнессу.

### Выборочные проверки на реальных моделях (Live Runs)

Live-тесты требуют активных харнессов и расходуют квоты аккаунтов. Они **никогда не запускаются автоматически в CI**.

Для ручной проверки моделей используйте скрипт `examples/debug_harnesses.py`:

```powershell
# Проверка доступности харнессов коротким запросом
.\.venv\Scripts\python.exe .\examples\debug_harnesses.py --part agents --agents codex

# Проверка отдельного файла по выбранным правилам
.\.venv\Scripts\python.exe .\examples\debug_harnesses.py --part smells `
  --target .\agent_code_checker\service.py `
  --rules long_method,large_class `
  --agents codex
```

## 4. Проверка документации и ссылок

Перед отправкой изменений:
- Убедитесь, что все относительные Markdown-ссылки в `README.md`, `README.ru.md` и папке `docs/` ведут на существующие файлы.
- Используйте в примерах только переносимые относительные пути (не используйте абсолютные системные пути вроде `C:\Users\...` или `D:\...`).
- Проверяйте соответствие сигнатур функций и флагов CLI актуальному коду в `agent_code_checker/cli.py` и `agent_code_checker/mcp_server.py`; каталог `qriterra/` предоставляет новый публичный интерфейс.

## 5. Чек-лист для Pull Request

- [ ] Новая функциональность покрыта тестами в `tests/`.
- [ ] Оффлайн-набор тестов проходит успешно: `python -m unittest discover -s tests -v`.
- [ ] В коммит не включены временные файлы отладки (`examples/debug-runs/`, сессии).
- [ ] Обновлены как английская, так и русская документация с сохранением взаимных ссылок.
